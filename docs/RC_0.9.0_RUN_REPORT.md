## 2. Что было исправлено в этом прогоне

### 2.1 Флакующий тест (P1) — `src/slaveContractsEngine.test.ts`

Тест `supports deadline/overdelivery KPI as a separate save-compatible stream`
падал примерно в половине прогонов.

Причина не в коде движка: `generateSlaveContract('market', 10)` бросает кубик на
покупателя, а вместе с ним — на `minQuality`. Фикстура полагалась на то, что
покупатель примет низкокачественного пойманного персонажа, поэтому падала
ровно тогда, когда выпадал покупатель с планкой `high`/`legendary`.

Исправление: планка качества в фикстуре закреплена (`minQuality: 'any'`).
Проверка: 12 прогонов подряд — **0 падений** (до правки — падения в половине
прогонов).

> Правило на будущее: ни одна фикстура не должна зависеть от `Math.random`.
> Если функция бросает кубик внутри, её вход нужно закрепить явно.

### 2.2 Версия продукта: хардкод → `package.json`

Бейдж в шапке был литералом `v0.4.0 Web`, пока пакет жил на `0.7.7` — расхождение
в две минорные версии. Теперь:

- `vite.config.ts` читает `version` из `package.json` и инжектит её как
  `__APP_VERSION__` через `define`;
- `src/env.d.ts` объявляет константу;
- `src/App.tsx` строит подпись как `v${__APP_VERSION__} Web` (`APP_VERSION_LABEL`);
- `vite build` кладёт в бандл `v0.9.0 Web`, старое значение в бандле отсутствует.

Поднято синхронно:

| Файл                                     | Было    | Стало       |
| ---------------------------------------- | ------- | ----------- |
| `package.json`                           | `0.7.7` | **`0.9.0`** |
| `package-lock.json` (root)               | `0.7.0` | **`0.9.0`** |
| `android/app/build.gradle` `versionCode` | `9`     | **`901`**   |
| `android/app/build.gradle` `versionName` | `0.6.6` | **`0.9.0`** |

Схема `versionCode` для Android: `MAJOR*10000 + MINOR*100 + PATCH` → `0.9.0` = `901`.

## 4. Известные предупреждения (baseline)

36 предупреждений `react-hooks/set-state-in-effect` в `App.tsx`: `setState`
вызывается прямо в `useEffect`. Ноль — недостижим без архитектурной правки
(эффекты используются как «computed state»). Политика на 0.9.0: **новые
предупреждения запрещены**, текущие 36 считаются принятыми до 1.0. Проверка
регрессии — сравнение числа `npm run lint -- -f json` с 36.

## 5. Найденные шероховатости (в backlog, не блокеры)

1. **Первый день календаря не очевиден.** Игрок открывает календарь и видит
   выбранным первый день недели, а не «сегодня» в смысле «день, который сейчас
   обрабатывается». Кандидат на 1.0: подсветка «текущего» дня отдельным стилем.
2. **`DayCalendar` не хранит выбранный день в сейве** — после перезагрузки
   календарь возвращается на первый день недели. Осознанно (не меняли формат
   сейва), но стоит записать в известные ограничения.
3. **Пустые дни говорят «ничего не запланировано»** только в панели дня, а в
   сетке месяца день без событий визуально ничем не отличается — кроме
   отсутствия точек. Кандидат на 1.0: точечный «фон» для пустых дней.
4. **36 предупреждений линтера** — см. §4.
